# 学園祭レジ Webアプリ

スタッフ専用のレジWebアプリです。メニュー・金額を一括管理して金額提示ミスを防ぎ、会計ログを Google スプレッドシートに記録します。
**現金のみ対応。アプリ上でのお金の通信・決済処理は一切ありません（記録のみ）。**

## 構成

```
GitHub Pages（画面: index.html / css / js）
        │  ログイン・メニュー読込/保存・ログ記録（すべてトークン必須）
        ▼
Google Apps Script（gas/Code.gs） ──► Google スプレッドシート
                         casino_logs   ├ casher_menu（メニュー）
                                       ├ casher_genres（ジャンル）
                                       ├ casher_logs（会計ログ）
                                       └ （既存の受付ログ）
```

- **ログイン必須**: ユーザー名/パスワードの確認は GAS 側（サーバー側）で行います。パスワードは GitHub には置かず、GAS のスクリプトプロパティにだけ保存されます。
  URL が来場客に流出しても、ログインできなければメニューの読込も会計ログの記録もできません。
- **メニューはスプレッドシートで共有**: どのPCで編集しても、他のPCに反映されます（メニュー画面に戻ったとき/5分ごとに自動再読込）。
- **casher_logs の形式**: `記録日時 / 会計日時 / 取引ID / レジ番号 / 点数 / 合計金額 / 預かり金額 / お釣り` の右に、**メニュー名の列が全メニュー分**並び、各会計の購入点数が数字で入ります（買っていないメニューは 0）。
  メニューを追加すると列は右端に自動で増えます。メニュー名を変えると新しい名前の列ができます（古い列は過去の記録用にそのまま残ります）。
- **ログ保存に失敗しても会計は止まらない**: 失敗した取引は「未送信ログ」としてPC内に保管され、30秒ごとに自動再送されます（ヘッダーのオレンジのバッジをクリックで手動再送）。取引IDで重複チェックしているので二重記録されません。
- **端末内バックアップ**: 各PCの取引履歴はブラウザ内にも保存され、「メニュー管理 → この端末の取引履歴CSV」でダウンロードできます。

## 画面

| 画面 | 内容 |
|---|---|
| 1. メニュー | ジャンル別グリッド。クリックで右の注文内容に追加（＋/−/削除可）。合計は赤字。Enterキーで内容確定 |
| 2. 内容確定 | 明細と合計。預かり金額を入力（全角数字OK・クイック金額ボタンあり）。合計以上のときだけ確定可能。Enterで確定 / Escで戻る |
| 3. 決済完了 | お釣りを大きく表示。ログ保存成功→緑のチェック、失敗→画面全体をオレンジの枠で囲む |
| 4. メニュー管理 | ジャンル（色）とメニュー（名前・ジャンル・ピクトグラム・金額）の追加/編集/削除/一時無効化/並び替え |

> 預かり金額は「合計と同額（ぴったり）」も確定できるようにしています。

## セットアップ手順

### 1. GAS を用意する（受付ログと同じスプレッドシート `casino_logs` に書き込む）
受付ログ側の GAS と関数名（`doPost` など）がぶつからないよう、**レジ用は別の GAS プロジェクト**として作り、
`gas/Code.gs` 冒頭の `SPREADSHEET_ID` でスプレッドシートを指定して書き込みます。

1. `casino_logs` の編集権限を持つ Google アカウントで <https://script.google.com> を開き **新しいプロジェクト**（名前は例: `casher`）
2. 最初からある `コード.gs` の中身を全部消し、[`gas/Code.gs`](gas/Code.gs) の中身を貼り付けて保存
3. 冒頭の `SPREADSHEET_ID` が `casino_logs` の ID になっていることを確認（URL の `/d/` と `/edit` の間）
4. `setup` 関数内の `USER` と `PASS` を、スタッフ共用のログイン情報に書き換える
5. 上部の関数選択で **`setup`** を選び **実行**（初回は権限の承認が必要です）
   → `casino_logs` に `casher_logs`（会計ログ）・`casher_menu`・`casher_genres` シートができます（既存の受付ログのシートには触りません）
6. 実行できたら、`PASS` の行を元の `'ここに強いパスワードを入力'` に戻して保存（パスワードはスクリプトプロパティに保存済みなので、コード上に残す必要はありません）

### 2. GAS をウェブアプリとして公開する
1. 右上の **デプロイ → 新しいデプロイ**
2. 種類: **ウェブアプリ**
3. 次のユーザーとして実行: **自分**
4. アクセスできるユーザー: **全員**（※認証はアプリ側のログインで行うため、これで問題ありません）
5. デプロイして表示される **ウェブアプリ URL**（`https://script.google.com/macros/s/.../exec`）をコピー

> `Code.gs` を後から修正した場合は **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン** で更新してください（URLは変わりません）。

### 3. 画面側に URL を設定する
[`js/config.js`](js/config.js) の `GAS_URL` にコピーした URL を貼り付けます。

```js
GAS_URL: 'https://script.google.com/macros/s/XXXXXXXX/exec',
```

### 4. GitHub Pages で公開する
1. スタッフ共用アカウントで GitHub にリポジトリを作成し、このフォルダの中身をアップロード
2. リポジトリの **Settings → Pages** で、Branch を `main` / `/(root)` にして保存
3. 数分後に表示される `https://<アカウント名>.github.io/<リポジトリ名>/` がレジのURLです

> 無料プランの GitHub Pages はリポジトリが公開（Public）になりますが、リポジトリにはパスワード等の秘密情報は含まれていません。
> `config.js` の GAS URL が見えても、ログインしない限り何もできない設計です。

### 5. 当日の使い方
1. 各PCで URL を開いてログイン（14時間有効。翌日は再ログイン）
2. 初回ログイン時に **レジ番号** を入力（ログにどのPCの会計か記録されます。ヘッダーからいつでも変更可）
3. 「メニュー管理」でジャンル → メニューの順に登録

## 運用メモ

- **パスワード変更**: GAS エディタで `setup` の値を書き換えて再実行（全PCのログインが無効になり、再ログインが必要になります）
- **ログインのロック**: パスワードを10回連続で間違えると10分間ロックされます。すぐ解除したいときは GAS エディタで `resetLoginLock` を実行
- **違算チェック**: スプレッドシートの「レジログ」シートで、レジ番号ごとに `合計金額` を合計すれば、そのレジの売上（＝増えているべき現金）が出ます
- **未送信ログが残っているPCは閉じない**: ヘッダーに「未送信ログ n件」が出ている間はネットワーク復帰を待つか、CSVを書き出してください

## ローカルでの動作確認（任意）

Node.js が入っていれば、以下で `http://localhost:8080` を開くとデモモード（ユーザー名 `demo` / パスワード `demo`、データはそのPCのブラウザ内だけ）で試せます。`GAS_URL` を設定すると本番のGASに接続します。

```bash
node tools/dev-server.js
```
